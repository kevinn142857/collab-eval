# 模型体检（Model Health Check）产品概念

> 日期：2026-08-24 ｜ 状态：概念稿 ｜ 上游：[评测框架设计.md](评测框架设计.md)

## 1. 一句话

AI Gateway 替用户持续回答一个问题：**「你的 AI 供应商是不是变了」**——模型降智、渠道偷换、量化降配，第一次有数据可查。

## 2. 为什么是网关来做

「感觉变笨了」= 模型 × 场景，两样平时一起变，用户自己分不开。固定探针集把场景冻住，只让模型变。而这件事只有中间层做得成：

| 角色 | 为什么做不了 |
|---|---|
| 模型厂商 | 没有动机证明自己降智 |
| 用户自己 | 没有基线、没有对照渠道、成本分摊不了 |
| 独立监测站 | 探针流量会被供应商识别并特殊照顾（跑分模式） |
| **网关** | **坐在中间：有各渠道的真实通路，可把探针混入真实流量，供应商无法区分** |

探针混流是本产品的护城河，也是转售渠道验真唯一可信的方式。

## 3. 三个对比

| 对比 | 回答的问题 | 数据来源 |
|---|---|---|
| 自己 vs 历史 | 这个渠道的这个模型，比上月变了没 | 用户渠道的探针时间线 |
| 渠道 vs 官方 | 你买的渠道和官方 API 是不是同一个东西 | 网关维护的官方基线 |
| 渠道 vs 渠道 | 同一模型哪家成色最好 | 各渠道探针横向对比（匿名聚合） |

## 4. 探针集构成

从协作智能评测题库抽轻量子集，三层：

| 层 | 内容 | 测什么 | 来源 |
|---|---|---|---|
| 能力探针 | 10 题有标准答案（数学/代码/抽取） | 有没有换小模型 | 引用公开题，定期轮换防泄露 |
| 协作探针 | 五维度各 2-3 题（含 1 组配对施压） | 有没有变得更顺从、更敷衍、更少主动——「降智感」的主要来源 | 评测题库子集，独有 |
| 行为探针 | 拒答率、输出长度分布、格式遵循率、截断率、首 token 延迟、上下文有效长度 | 量化/降配最先反映在这些指标上 | 网关侧统计，零额外成本 |

运行参数：每渠道每周一轮，每题采样 5 次，温度固定，探针版本号入库。新绑定渠道当天跑首轮存为基线。

## 5. 报告样式

- 五维度 + 行为指标时间线，每点带 bootstrap 95% 置信区间
- 超出区间自动标黄/标红，附前后回答样本对照
- 渠道对比页：同模型各渠道雷达图 + 「与官方基线差值」

**措辞边界（必须遵守）：** 只说「行为相对基线变化 ±X%，超出/未超出置信区间」；不说「降智」「偷换」「欺诈」。原因（权重更新、安全层调整、路由变化、量化）从外部不可判，证据给足，结论留给用户。对外榜单化之前须过法务。

## 6. 防对抗

供应商或渠道可能针对探针优化：

1. **混流**：探针经用户真实流量通道发出，请求特征与真实流量一致
2. **轮换**：能力探针每季度换题；协作探针从私有题库轮抽，单题不重复使用超过两轮
3. **私有集**：协作探针题面不公开，只公开维度定义与方法
4. **蜜罐**：保留少量已公开的旧题，若某渠道旧题分数异常高于私有题，标记「疑似针对性优化」

## 7. 与评测项目的关系

```
评测框架（方法，开源）→ 题库（资产，私有）→ 榜单（影响力）→ 模型体检（商业化出口）
```

- 评测框架为体检提供协作探针与判分方法（核对清单 + LLM 评委）
- 体检为评测反哺真实数据：用户授权的失败样本可加工为新题（走脱敏 + 四问表单流程）
- 立项答辩口径：评测是上游研发，体检是下游产品，网关是分发通道

## 8. 商业化与成本

- 成本：每渠道每周一轮 ≈ 数十元（探针 ~40 题 × 5 采样 × 判分），行为探针零成本
- 形态：网关增值功能（按渠道数订阅），或作为高级套餐权益
- 冷启动：先对网关自身支持的主流模型渠道免费出公开周报（引流 + 积累基线），再开放用户自有渠道付费监测

## 9. 风险

| 风险 | 应对 |
|---|---|
| 采样噪声导致误报 | 置信区间 + 连续两轮超限才告警 |
| 供应商公关/法律压力 | 措辞边界（§5）；只呈现数据不定性 |
| 协作探针判分依赖 LLM 评委 | 评委模型与被测模型分离；定期人工抽查校准 |
| 探针题泄露 | §6 轮换 + 私有集 + 蜜罐 |

## 10. 下一步

1. 评测框架阶段 0-2 先行（参考脚手架 + L1 题库），体检复用其产出
2. 行为探针可先行上线——纯网关侧统计，不依赖题库，工程量最小、见效最快
3. 概念验证：选 2 个公开渠道 + 官方 API，同一模型跑 4 周探针，看能否稳定检出已知差异（如量化版）
