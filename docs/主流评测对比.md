# 主流评测分析与本框架对比

> 日期：2026-08-22 ｜ 配套文档：[评测框架设计.md](评测框架设计.md)

## 1. 主流评测分三类

### 1.1 能力榜（静态题库，有标准答案）

| 评测 | 测什么 | 2026 状态 |
|---|---|---|
| MMLU / MMLU-Pro | 57 学科知识选择题；Pro 版改 10 选项 + 强制思维链 | MMLU 已饱和（顶级模型 88-94%，人类专家上限约 89.8%），无法区分前沿模型 |
| GPQA Diamond | 博士级科学问答 | 前沿模型 90%+，接近饱和 |
| HLE（Humanity's Last Exam） | 专家出题的跨学科难题 | 2025 初最好模型 < 10%，2026 初 30-35%，仍有区分度 |
| SWE-bench Verified | 修真实 GitHub issue，跑测试验收 | 2023 年 4.4% → 2026 年 80-90%，已饱和 |
| HELM | 200+ 场景 × 7 维度（准确、校准、鲁棒、公平、偏见、毒性、效率） | 2026-06-01 进入维护模式 |

共同特征：**单轮、用户先开口、有唯一正确答案、被测对象是裸模型。** 测的是「会不会」。

### 1.2 智能体榜（环境交互，任务完成率）

| 评测 | 测什么 | 值得注意的设计 |
|---|---|---|
| Terminal-Bench 2.0 | 真实命令行环境里多步执行、出错恢复、通过隐藏测试 | 环境真实，但任务仍是「给定明确目标」 |
| τ²-bench | 零售/航空客服场景，带工具 API 和政策文档 | **政策遵守**：订对了机票但违反改签费政策即判失败——这是「执行层边界感」的现成实现 |
| GAIA | 通用助手任务（检索 + 推理 + 工具） | 人类 92%，模型长期远低于此 |
| OSWorld | 真实桌面 GUI 操作 | 截图进、鼠标键盘出 |
| BrowseComp | 长程网页检索，判断何时需要再搜 | 测「知道自己还不知道」 |

共同特征：**目标由题目给定、单次会话、被测对象是模型 + 脚手架但很少要求申报。** 测的是「能不能做完」。

两个已被公开证实的问题：
- **脚手架效应**：同一模型换一套 harness，分数差异显著（多篇 2026 年综述均指出）。
- **奖励欺骗**：2026-04-12 UC Berkeley 发布研究，一个自动扫描智能体攻破了全部 8 个主流智能体基准，不解决任何任务即可拿到接近满分。

### 1.3 偏好榜（人类投票）

| 评测 | 测什么 | 已知问题 |
|---|---|---|
| LMArena（原 Chatbot Arena） | 匿名双模型回答，用户投票，Bradley-Terry 排序 | 「Leaderboard Illusion」（2025-04）指出大厂选择性披露、私下测多个变体；格式刷票；厂商动员社区投票。平台已加风格控制、匿名强制、最低票数门槛 |

特征：**测「用户更喜欢哪个」，不测「哪个更对」。** 讨好用户的回答天然占优——这正好与本框架维度 3「明确表态、敢于反驳」方向相反。

## 2. 逐项对比

| 维度 | 能力榜 | 智能体榜 | 偏好榜 | 本框架 |
|---|---|---|---|---|
| 被测对象 | 裸模型 | 模型 + 脚手架（不申报） | 裸模型 + 厂商提示 | 两条赛道分开，**均须申报** |
| 谁先开口 | 用户 | 题目 | 用户 | L1 用户；**L2 无人开口，测时机** |
| 有无标准答案 | 有 | 有（测试/状态校验） | 无 | L1 有（埋点清单）；L2 有（should_act / should_not_act） |
| 多轮 | 否 | 单会话多步 | 单轮为主 | L1 多轮追问；L2 跨会话 |
| 测意图理解 | 否 | 否（目标已明确） | 间接 | 是（true_intent） |
| 测主动发现问题 | 否 | 否 | 否 | 是（planted_issues） |
| 测敢于反驳 | 否 | 否 | **反向**（迎合占优） | 是（配对施压） |
| 测该不该动 | — | 否 | — | 是（FDR / MNR） |
| 测边界 | — | τ²-bench 有（政策遵守） | — | 两级：提议越界 / 执行越界 |
| 跨会话记忆 | 否 | 否 | 否 | L2 有（memory_seed） |
| 反向指标 | 无 | 无 | 无 | 打扰代价、越界封顶 |
| 抗刷分 | 饱和即失效 | 已被全部攻破 | 刷票 | 冗长版 vs 精准版对照、评委盲测 |

## 3. 结论

### 3.1 主流评测的共同盲区

三类评测都假设**「任务已经被人定义好了」**——要么用户开口，要么题目给目标。没有任何一个主流评测测「没人说话时该不该说、说什么」。而 ProEvent 的数据（顶级模型误触发率 > 90%）说明这恰恰是差距最大的能力。

第二个盲区是**判断力**。能力榜测知识，智能体榜测执行，偏好榜测讨喜；「指出用户前提错了」在三类评测里要么不测、要么被惩罚。

### 3.2 本框架的定位

不是替代，是补位：

```
         会不会（能力榜）  →  能不能做完（智能体榜）  →  该不该做、何时做（本框架）
```

本框架的模型赛道 L1 与能力榜互补（知识 vs 判断），智能体赛道 L2 与智能体榜互补（完成给定目标 vs 自己发现目标）。

### 3.3 该抄的

| 来源 | 抄什么 | 用在哪 |
|---|---|---|
| τ²-bench | 政策文档 + 违反即失败 | L2/L3 执行层边界：把「用户阈值」「禁止动作」写成政策文档 |
| HELM | 多维度分开报告，不合成单一分 | 两条赛道分开出榜，五维度分开展示 |
| LMArena | 双回答盲比 | 评委校准：冗长版 vs 精准版配对比较，而非单独打分 |
| SWE-bench Verified | 人工验证题目质量 | 题库入库前双人核对埋点 |
| Berkeley 奖励欺骗研究 | 自动攻击基准 | 题库上线前跑一轮「不解题只刷分」攻击，找清单漏洞 |

### 3.4 该避的

- **不做单一总分**：Arena 和 MMLU 的教训都是单一数字被过度解读。
- **不接受未申报的脚手架/提示成绩**：这是智能体榜公信力崩塌的直接原因。
- **不靠难度抗饱和**：HLE 的路线是题更难；本框架的区分度来自「时机」和「判断」，这两样不会因为模型知识更多而饱和。
